作业框架分析

整体看就是上次作业加上 BVH 加速。

几个独立出来的类 (Ray、Intersection、Material)

上次作业中光线、交点、材质的信息都是分散在多个变量中的，这次它们被组织成单独的类，稍微看一下。

光线 Ray 的成员：

  • 起点、方向、到交点的 t
  • 以及 t_min 和 t_max 表示光线的有效范围，这里设定：
    • t_min = 0.0
    • t_max = std::numeric_limits<double>::max()

交点 Intersection 的成员：

  1. happened 表示是否相交，如果为 false 就不相交不用再看了
  2. coords 交点坐标
  3. normal 交点处的法向量
  4. distance 交点与光线起点的距离，就是 Ray 中的 t，这是便于从多个交点中找到最近的那个
  5. obj 交点所在物体，m 物体材质

材质 Material 的成员，这里就说一个新面孔 m_emission —— 材质自身发的光，但目前还没用上。

BVH 加速结构

这里的 BVH 有两层，Scene 级的和 Object 级的：

  • Scene 将 std::vector<Object*> objects 中的物体分到若干 BVH 中
  • MeshTriangle 会将所有 Triangle 分到若干 BVH 中

最后看下 BVH 的构建过程

先是 BVHAccel 的内容：

  1. SplitMethod：有两种划分模式 NAIVE 和 SAH，前者是朴素的中位数划分法，已经实现了；后者是更高级的 SAH (表面积启发式) 划分法，是拓展作业
  2. BVHBuildNode 即 BVH 树的节点
  3. std::vector<Object*> primitives：“primitive” 被称作基本几何元素，BVH 划分时就把一堆 primitives 划分到不同节点中
    • 对 Scene 级，primitive 可以是球、MeshTriangle
    • 对 Object 级，primitive 可以是 MeshTriangle 中的一个 Triangle
  4. maxPrimsInNode 每个 BVH 叶节点最多的 primitive 个数

然后是 NAIVE 模式划分 BVH：这块代码写得不是很好呢

  1. 缺陷 1：最开始计算 bounds 是冗余代码，后面没有用到
  2. 缺陷 2：递归的终止情况是 objects.size() = 1 或 2，并没有考虑 maxPrimsInNode，这是默认按 maxPrimsInNode = 1 写死的
  3. 关于划分方法
    • 先求所有 bounds 中心点的总 bound，划分最长的边
    • 划分时，将每个 primitive 的 bounds 的中心点排序，然后从中间一分为二

包围盒求交实现

判断光线与 AABB 包围盒相交在 Lecture 13 中讲过，需要根据光线方向的正负判断每对面中哪个进哪个出。包围盒求交会调用超多次，如果用 if，分支预测错误会消耗很多流水线时钟周期，所以又用了 dirIsNeg 来消除分支语句。

拓展作业：SAH 实现

参考这篇 2014 年的博客，话说这是多少年以前的算法了…

SAH 用了一点点概率论。划分 BVH 节点时，设得到的两个子包围盒分别为 A、B，里面 primitive 个数分别为 nAn_AnA​、nBn_BnB​，设光线与两个子包围盒相交的概率分别为 pAp_ApA​、pBp_BpB​。

光线要与 primitive 求交，SAH 的目标是选出可以让平均求交次数最小的划分位置。于是，让我们加入亿点点的贪心和近似：

  1. 设光线与当前节点相交后，需要求交 costcostcost 次
  2. 光线与 A、B 相交时需要求交的次数分别近似为 nAn_AnA​、nBn_BnB​，是的就这么简单粗暴
  3. 令 A、B 组成的整个大包围盒是 C，表面积分别为 SAS_ASA​、SBS_BSB​、SCS_CSC​。光线与 A、B 相交的概率分别近似为 SASC\frac{S_A}{S_C}SC​SA​​、SBSC\frac{S_B}{S_C}SC​SB​​
  4. cost=nA⋅SASC+nB⋅SBSCcost = n_A\cdot\frac{S_A}{S_C} + n_B\cdot\frac{S_B}{S_C}cost=nA​⋅SC​SA​​+nB​⋅SC​SB​​
  5. 对每个不同划分都算一遍 costcostcost 太费时间，所以只在有限的候选位置中选择。将 x/y/z 轴划分为 BBB 个 bucketbucketbucket，只考虑 B−1B-1B−1 个划分位置。下图是 B=6B=6B=6 的情况，注意 buckets 的范围是最远两个 primitive 包围盒的中心
  6. x/y/z 轴各算一遍，选出最小的 costcostcost
